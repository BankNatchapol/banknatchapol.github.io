## Overview

**decoderd** is a low-latency decoder daemon designed to sit between the classical control stack and the quantum error correction cycle. Syndrome data arrives every ~1 µs per surface-code round, and the decoder must return a correction within 2–5 µs to avoid back-action. Standard socket I/O introduces kernel jitter pushing latency into the tens of microseconds — `decoderd` eliminates this with POSIX shared memory as the data transport.

## How It Works

At startup the daemon memory-maps a fixed-size ring buffer shared with the control stack process. Syndrome packets are written directly into this buffer by the FPGA driver. `decoderd` spins on an atomic lock-free sentinel rather than blocking on `recv()`, avoiding syscall overhead entirely.

The correction is written back as a 1-byte Pauli frame update. Each frame uses a simple binary protocol: 2-byte magic number, 2-byte syndrome-round counter, variable-length syndrome bitstring. Serialisation overhead is under 50 ns per frame.

## Results

- Average round-trip latency under **800 ns** (vs. ~12 µs for Unix socket equivalent)
- CPU affinity pinned; ring buffer resident in L3 cache
- Decoder algorithm (union-find) is a pure Rust library crate with zero unsafe code
