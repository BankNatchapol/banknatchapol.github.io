## Overview

**VirtualSoul** is an autonomous AI VTuber desktop application — a character avatar that streams live on YouTube and Twitch 24 hours a day without a human behind the keyboard. It reads incoming chat messages, generates in-character responses via LLM, speaks them in Thai with sub-second latency TTS, and drives a VTube Studio avatar with synchronized animations. When chat goes silent, it generates its own monologue to keep the stream alive.

Built in 2023 — before LangChain, before AutoGen, before the term "agentic AI" was widely used. Everything was engineered from scratch: the agent harness, the context system, the memory architecture, the multi-subprocess coordination.

---

## Architecture: multiple agents cooperating

The system runs five concurrent agents, each in its own subprocess, coordinated by a central harness:

| Agent | Role |
|-------|------|
| **LLM agent** (GPT-4 via Flask) | Generates character responses |
| **TTS agent** (Azure Neural TTS) | Synthesizes Thai speech from text |
| **STT agent** | Converts microphone input to text |
| **Chat reader** (YouTube / Twitch) | Ingests live chat messages |
| **Avatar controller** (VTube Studio) | Triggers animations and facial parameters |

The harness (`wAIfu`) monitors all subprocess states, respawns crashed agents, and manages the shared command queue — so the stream never goes down even if a single service fails.

---

## The Main Loop

Every cycle:

1. **Get input** — poll live chat, or fall back to monologue if chat is silent
2. **Sanitize** — filter bad words, deduplicate repeated messages
3. **Build prompt** — inject long-term persona + short-term conversation history
4. **LLM call** — generate in-character response
5. **TTS** — synthesize Thai speech; interrupt if a higher-priority message arrives
6. **Avatar** — fire VTube Studio hotkeys for lip sync and emotion animations
7. **Store** — append exchange to short-term memory

## Harness, context and memory engineering

This was the core engineering challenge — getting a consistent, believable, low-latency character without any agent framework to lean on. Every tool that exists in modern agentic stacks had to be built by hand.

### SubProc — Process Manager

Each agent runs as a `SubProc` instance tracking its OS process, API URL, and `running` state. When a subprocess crashes mid-stream, `reinit()` rebuilds the full runtime — reloads config, re-detects devices, respawns all processes with an incremented cycle counter — without touching the ongoing session.

```javascript
class SubProc {
  process = null;  api_url = '';  running = false;
  constructor(port) { this.api_url = port; }
}
```

### Context Engineering

Each LLM prompt is assembled from three layers before every call:

- **Character persona** — name, gender, personality traits, speaking style, characteristic topics
- **Language rules** — explicit Thai politeness particles (ครับ / ค่ะ), tone constraints, hard limits on what the character discusses
- **Example dialogues** — few-shot examples that anchor the character voice and response format

### flattenMemory() — Context Assembler

A dual-tier memory system keeps the character coherent across long streams. Before every LLM call, a single function assembles the full context window:

```javascript
function flattenMemory(additional) {
  while (wAIfu.memory.short_term.length > 4) {
    wAIfu.memory.short_term.shift();
  }
  return wAIfu.memory.long_term + additional
       + wAIfu.memory.short_term.join('');
}
```

- **Long-term**: Character definition and behavioral rules — constant across the session
- **Short-term**: Last 4 `[Chatter]: msg / [Character]: response` exchange pairs — trimmed automatically to keep context within budget

### Chat Sanitizers

`getTwitchChatOrNothing()` and `getYoutubeChatOrNothing()` are identical in contract but different in transport — Twitch uses a live WebSocket feed while YouTube chat is written to `./youtube/msg.txt` and watched with Chokidar. Both apply the same pipeline: blacklist check → deduplication → command-prefix filter → return sanitized `{ text, sender }` or nothing.

### TTS Interrupt

When a higher-priority message arrives while the character is speaking, `wsINTERRUPT` hits the TTS subprocess's `/interrupt` endpoint and immediately clears the live caption file — cutting speech mid-sentence and starting the new response. This was essential for keeping latency low when chat moved fast.

```javascript
fetch(TTS.api_url + '/interrupt').then(() => {
  fs.writeFileSync('./captions/transcript.txt', '');
});
```

### WebSocket Command Router

`handleSocketMessage` routes 8 command types from the control panel UI to the running harness in real time — no restart needed:

`MSG` · `CONFIG` · `CHARA` · `DEVICE` · `START_VOICE_INPUT` · `STOP_VOICE_INPUT` · `START_LIVE` · `STOP_LIVE` · `VTUBE_CONNECT` · `VTUBE_SET_DEFAULT`

### VTube Studio Bridge

`vtubeTriggerHotkey()` looks up hotkey IDs from a pre-cached `hotkey_map` and fires them via the VTube Studio WebSocket API. During singing, `vtubeDance1()` and `vtubeDance2()` drive real-time facial parameters (`FaceAngleX/Y/Z`) through choreographed step arrays — each loop checks `wAIfu.is_singing` and exits cleanly if the singing mode is cancelled.

### Monologue Fallback

When no chat arrives, the harness picks a topic from the character's interest list and generates unprompted commentary — keeping the stream from going silent without any human input.

## Character interaction

Responses are shaped by two signals:

- **Watcher input** — direct chat messages, moderator commands, TTS requests
- **Response semantics** — the character's `craziness` and `creativity` parameters tune how far the LLM drifts from the literal prompt, producing personality variation per response

Moderators can send real-time commands (`!reload`, `!say`, `!pause`) that the harness interprets directly, without going through the LLM.

---

## Control panel

A desktop UI (Electron + WebSocket) gives the streamer full control without stopping the stream:

- Switch between **text input**, **voice input**, and **live chat** modes
- Configure character name, persona, language, and speaking style
- Set TTS pitch, speed, and expressiveness
- Toggle YouTube and Twitch chat simultaneously
- Connect / reconnect VTube Studio
- Pause and resume the agent loop

All changes propagate to the running harness in real time via WebSocket messages.

## Game integration

Beyond conversation, the character can actively participate in games — giving it something to *do* on stream rather than just reacting to chat.

### Drawing Game (Gartic.io)

A custom drawing engine controls the mouse to draw on the Gartic canvas. The character receives a word prompt, generates a drawing plan, and executes it through programmatic mouse movements — producing recognizable (if imperfect) drawings that the audience can guess. The drawing behavior is part of the character's persona, not a generic bot.

### GeoGuessr

A vision pipeline takes screenshots of the game's street view, passes them to GPT-4V for scene analysis — reading signs, vegetation, road markings, architecture — and generates a location guess with reasoning. The character narrates its thought process live in Thai as it looks for clues, making the reasoning part of the entertainment.

### Architecture

Both integrations share the same harness loop — game state is just another input type, and the character's response (speech + action) flows through the same LLM → TTS → avatar pipeline. Each game has its own module that translates game state into prompts and translates LLM output back into physical actions (mouse draw, map click).
