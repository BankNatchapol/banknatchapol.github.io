## Overview

**AI Novel Writer** is a one-shot generation tool that produces a complete, structured novel with character illustrations from a single JSON configuration file. Given a theme, language, characters, and writing style, it generates everything in sequence — title, two-paragraph summary, character profiles, table of contents, chapter introductions, and full section content — with a living character state that updates as the story progresses.

Built in 2023 — before LangGraph, before mature agent frameworks, at a time when "context engineering" and "memory management" had to be implemented by hand from raw API calls.

---

## What It Produces

From one input file, the tool writes an entire novel:

| Artifact | Description |
|----------|-------------|
| Title | Normalized for the target language |
| Summary | Two-paragraph story overview |
| Character profiles | JSON with traits, relationships, image prompts |
| Character illustrations | AI-generated images per character |
| Table of contents | Structured chapter/section plan |
| Chapter content | Introduced with key topics per chapter |
| Section content | Full prose with dialogue, iteratively extended |
| Section illustrations | Images generated per scene |
| Cost report | Token usage and API cost per generation step |

## Generation Pipeline

The tool works through a fixed sequence of 11 specialized prompt functions, each building on the output of the previous:

1. **`summary()`** — generates a two-paragraph story overview from user description or free-form AI decision
2. **`character_contents()`** — produces detailed character profiles as structured JSON
3. **`table_of_contents()`** — generates the full chapter/section structure as JSON
4. **`character_des()`** — converts character descriptions into image generation prompts
5. **`_write_characters_images()`** — calls the image model per character
6. **`chapter_topics()`** — lists 3 key topics per chapter; receives previous topics to prevent repetition
7. **`chapter()`** — writes the chapter introduction using recent chapters as context
8. **`section_topics()`** — lists 3–6 topics for each section
9. **`section()`** — writes full section prose with dialogue; iteratively extended with `continue` prompts between a configured min/max count
10. **`_write_img()`** — summarizes section text, generates a scene illustration
11. **`checker()`** — post-processes each output to fix language errors and strip repetition

## Context & Memory Engineering

The core challenge of generating a coherent novel is that LLMs have no memory across calls. Every piece of narrative continuity had to be engineered explicitly.

### History-Based Context

Every generation function receives a `history` list — a sequence of role/content messages that accumulates the entire book context up to that point:

```python
history = [
  {"role": "system", "content": "<book metadata, summary, characters, TOC>"},
  {"role": "user",   "content": "<previous generation prompt>"},
  {"role": "assistant", "content": "<previous generation output>"},
  ...
]
```

Each new prompt is appended to this history before the API call, so the model always writes with full awareness of everything generated before it.

### Token Budget Management

As the novel grows, the history grows with it. `_check_num_tokens()` enforces a hard token limit by removing the oldest messages when the total exceeds the model's context window — a manual sliding window before any framework had this built in. When a prompt itself is too long, `prompt_summarize()` compresses it to under 1024 tokens.

### Living Character State

Characters are not static descriptions. After each chapter, `update_character_contents()` re-reads the prior character JSON and the current chapter content, then writes an updated character state — tracking relationship changes, story developments, and character arc progression. This updated state feeds into all subsequent chapters, so characters behave consistently as the story evolves.

### Chapter & Section Continuity

- **`chapter()`** receives the text of the most recent chapters concatenated as context
- **`section()`** receives the most recent sections
- **`chapter_topics()`** and **`section_topics()`** receive previously generated topics to avoid repetitive plot beats

## Multi-Model Orchestration

Different tasks are routed to different models based on capability:

- **Reasoning / structure** (summary, TOC, character JSON) → Google Vertex AI (Gemini)
- **Long-form prose** (chapters, sections) → GPT-4 or Claude
- **Image generation** → DALL·E (OpenAI)

A unified API layer (`callOpenAI()`, `callVertexGemini()`, `callGemini()`, `callClaude()`) wraps each platform with consistent retry logic and exponential backoff, so the orchestrator is model-agnostic.

---

## Resume Capability

All generation state is serialized to `book.json` after every step. If the process is interrupted mid-novel, it resumes from the last completed step rather than restarting from scratch — critical for long runs that could take 30+ minutes and cost non-trivial API fees.

## Configuration

The input JSON supports anything from minimal to fully specified:

- Book metadata: title, theme, language, image style
- Character definitions with names, traits, and relationship maps
- Per-chapter and per-section overrides (emotion, section count, image count)
- Chapter writing templates for consistent prose style
- Model selection per task
